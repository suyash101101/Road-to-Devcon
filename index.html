Chapter 1 · Why any of this exists

What is a ledger?

A ledger is a list of who owns what, and who paid whom.

Your bank account is a ledger. UPI balances are a ledger. Your college fee portal is a ledger. Someone has to store the rows and decide which writes are allowed.

Ask the room: who owns the SBI ledger? Who can freeze your account? Plant the trust question.

The normal setup

One company keeps the book

Central ledger

  • Bank / Paytm / college office owns the DB
  • You send them a request: "debit me, credit her"
  • They decide if it succeeds
  • You cannot verify their private database

What can go wrong?

  • They can freeze you
  • They can lie about balances
  • They can go bankrupt
  • Governments can force edits

This works most days. The question is: what happens when the trusted middleman fails?

Keep it concrete. Not anti-bank ideology. Just engineering: single point of trust.

2008

Trusted middlemen broke

Banks held the ledgers. Risk exploded. Bailouts happened. Ordinary people ate the loss.

You do not need macroeconomics. One line is enough: the people keeping the books could fail, and the public had no independent copy to verify.

In 2008 someone asked: can we have a ledger that nobody owns, that anyone can check?

Short history beat. Then Satoshi as engineering response, not religion.

The big idea

What if thousands of strangers kept the same copy of the ledger, and maths stopped secret edits?

That is Bitcoin's bet. A public notebook. Everyone can read. Writing needs proof of work (we will show how).

Land the idea before any mining jargon. Shared notebook.

Chapter 2 · How a shared notebook works

Three pieces only

  1. Transaction: a signed message. "Alice sends 1 coin to Bob." Anyone can check the signature.
  2. Mempool (waiting room): signed messages sit here until they are written into a page. We will simulate this live later.
  3. Block: a page of the notebook. A batch of transactions that the network accepts as history.

Chain of blocks = the full history. That is why people say "blockchain."

Introduce mempool softly as waiting room. Deep dive in chapter 5.

The hard problem

Who gets to write the next page?

If anyone can add a page, cheaters invent fake money. If one company adds pages, we are back to a bank.

Bitcoin's answer: make writing expensive. Computers race to solve a hard puzzle. Winner appends the next block. We call this Proof of Work (PoW).

Problem first, name second. Then go to interactive mining.

What you should remember

PoW in one breath

  1. Transactions wait in a public room.
  2. Miners compete to solve a puzzle.
  3. Winner publishes a block. Others check it and copy it.
  4. Honest majority + costly work ≈ hard to fake history.

Later Ethereum switches from PoW to Proof of Stake (PoS): stake coins instead of burning electricity. Same idea of "who may propose the next page," different cost.

One sentence on PoS only. No debate.

Chapter 3 · Ethereum

Bitcoin moves coins. Ethereum also runs programs.

Think: shared spreadsheet that can compute, not only store balances.

That is why people build apps (DEXs, NFTs, DAOs) on Ethereum. The logic lives next to the money, in the same public state.

Bridge clearly. Money ledger → programmable ledger.

The question everyone asks

Where is this "CPU"? Where does the EVM stay?

Not in one Amazon region. Not in MetaMask. Not in "the cloud."

Pause. Let them guess. Then reveal: every full node.

Answer

The EVM runs on every full node

A node is a computer (laptop, server) running Ethereum software. Each full node stores the state and re-executes every transaction. The EVM is the rule engine inside that software. Same bytecode in → same new state out. If they disagree, they are not on the same chain.

Press Run tx. Every node updates the same way.

Each card is one node. Each has a tiny EVM and a copy of state.

Emphasize: MetaMask talks to ONE node via RPC. That node is in the peer network. Consensus is "we all got the same answer."

Postgres vs Ethereum

Same "table," different ownership

Postgres at a company

  • One owner
  • Private writes
  • You trust the DBA
  • SQL runs on their server

Ethereum state

  • Many independent owners (nodes)
  • Public writes (after consensus)
  • You verify by re-running
  • EVM runs on every full node
CS students click hard on this. INSERT costs gas. SELECT via eth_call is usually free.

Accounts without usernames

You hold keys. You do not "log in."

Private key

Secret random number. Proves you authorize a tx. Never share. Never screenshot.

Address (EOA)

Public ID derived from the key. Like an account number. Safe to share.

Wallet app

MetaMask etc. Stores keys and helps you sign. The wallet is not the bank. It is a key manager.

EOA = Externally Owned Account. A human-controlled account (key), not a contract.

Show MetaMask address if set up. Never show seed phrase.

A transaction is just a signed message

From intent to network

  1. You choose an action (send ETH, call a contract).
  2. Wallet builds a transaction object (to, value, data, gas fields).
  3. Your private key signs it. Signature proves it was you.
  4. Wallet sends it to a node over RPC (HTTPS to Alchemy/Infura/your node).
  5. That node gossips it to peers. It enters the waiting room.
Tie to Week 4 RPC idea without naming too much. Browser cannot speak P2P directly.

Interactive · code to bytecode

What actually gets deployed?

You write Solidity (human readable). The compiler produces bytecode (what the EVM executes) and an ABI (JSON menu so wallets know how to call functions).

1. Soliditycontract Counter { ... }
2. solc compileCompiler checks types, emits artifacts
3. BytecodeHex ops the EVM understands
4. Every nodeStores code at an address, re-runs calls
Click Step to walk the pipeline.
No opcodes. Hex is the "body." ABI is the menu. Deploy = upload bytecode in a tx.

Paying for the shared CPU

Gas = bid for computation and block space

Every EVM operation costs gas. You set how much you are willing to pay. Higher tip usually means faster inclusion. Same auction idea as "who gets into the next block first."

Why gas exists

  • Stops infinite loops from freezing the network
  • Pays validators / prioritizes scarce block space
  • Makes spam expensive

Mental model

  • Uber surge pricing for CPU
  • Complex contract = more gas
  • Failed tx can still cost gas
Connect to mempool fee race coming up.

Chapter 4 · Smart contracts

A smart contract is a public program with public memory

Once deployed, the code sits at an address on the chain. Anyone can read the code and the storage (usually). Anyone who pays gas can call the functions (unless you restrict them).

It is not a legal contract. It is a program the network is forced to run the same way everywhere.

Repeat the public program / public memory line twice.

Building blocks

Four ideas before code

State variables

Stored forever on-chain (until changed). Like columns in a DB row owned by the contract.

Functions

The API. Some only read (view). Some change state and need a transaction + gas.

msg.sender

The address that signed this call. Your identity for this request. No password.

Visibility

public / private / internal / external. Who is allowed to call this function.

Tie msg.sender to "who clicked." Visibility can be light.

Example 1 · Counter

Line by line

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Counter {
    uint256 public count;   // public memory on-chain

    function inc() public {
        count += 1;            // anyone can bump, if they pay gas
    }

    function incBy(uint256 n) public {
        count += n;
    }
}

public count auto-creates a free getter. inc changes state, so it needs a real transaction.

Walk each line. Ask who is msg.sender when you call inc.

What happens when you call inc()

  1. Wallet builds a tx targeting the contract address, data = function selector for inc().
  2. You sign and broadcast. Tx enters the mempool.
  3. A block includes it. Every node runs the EVM: load code, execute inc, write new count.
  4. Explorers show the new state. Your wallet balance paid gas.

Reading count usually does not need a transaction. Changing it does.

Close the loop with chapters 3 and 5.

Example 2 · balances

A token is mostly a mapping

mapping(address => uint256) public balances;

function transfer(address to, uint256 amt) public {
    require(balances[msg.sender] >= amt, "not enough");
    balances[msg.sender] -= amt;
    balances[to] += amt;
}

"Sending tokens" is not FedEx. It is subtract from one key in a hash map, add to another. DEXs swap these mappings. That is what sandwich attacks target.

Plant DEX idea for MEV. Do not teach full ERC-20.

Solidity gotchas for beginners

Things that surprise CS students

  1. No floats. Money uses big integers (often 18 decimals). 1 ETH = 10^18 wei.
  2. Bugs are forever (mostly). Deployed code is hard to patch. Test like crazy.
  3. Everything public by default culture. Treat storage as readable.
  4. require reverts the call if false. Good for checks.
  5. Gas matters. Loops over huge arrays can brick users.
Light security mindset without Week 3 reentrancy deep dive.

Chapter 5 · The waiting room

Name it: mempool

Memory pool. Pending transactions that are not in a block yet.

Anyone running a node (or using a public RPC / explorer) can often see these pending messages: where value is going, which contract you call, how much gas you bid.

If it is pending, treat it as already public.

mempool.space is down. Our simulator is the live demo.

How it spreads

Gossip, not upload-to-one-server

  1. Your wallet sends the signed tx to one node (RPC).
  2. That node tells its peers. They tell their peers.
  3. Seconds later, many nodes hold a copy in their mempool.
  4. Searchers watch this feed for profitable opportunities.
One liner gossip. Bridge to MEV.

Why this freaks people out

Your intent leaks before confirmation

What observers see

  • Swap size and direction
  • Destination addresses
  • Contract calls and arguments
  • How urgently you bid (gas)

What they can do

  • Copy your trade
  • Front-run / sandwich you
  • Profile wallet habits over time
  • Censor or delay (in extreme cases)
Emotional beat before MEV definition.

Chapter 6 · Extraction

MEV

Maximal Extractable Value: profit from choosing which transactions go into a block and in what order.

Formerly called Miner Extractable Value. Same idea with validators and block builders. Searchers scan the mempool for profitable reorderings.

One clean definition. Then sandwich.

Sandwich attack

Victim wants to swap. Searcher eats both sides.

Front-run

Searcher buys first with higher fee. Price moves up.

Victim swap

Large buy sits in mempool. Slippage tolerance is the attack budget.

Back-run

Searcher sells into the victim. Pocket the spread.

Step 0: Victim tx is public intent. Click through 1 → 2 → 3.

Bigger than DeFi

Public chain = group chat for money
