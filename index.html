Part 01 · Context

2008

Banks were the trusted middlemen.
Then they broke.

Paint the scene quickly — housing crash, bailouts, "too big to fail." You don't need macroeconomics. One line: people realised the people keeping the ledger can lie, freeze accounts, or get bailed out while you eat the loss. That's the emotional setup for Satoshi.

The question

What if the ledger
needed no trusted party?

Satoshi's whitepaper was an engineering answer to a trust failure.

Say "Satoshi" once, don't mythologise. Land on the core idea: a ledger everyone can verify, no one can secretly edit. Analogise to a shared Google Sheet that nobody owns — except with maths instead of Google.

Core idea

Bank ledger

  • One owner
  • Private writes
  • You trust them

Bitcoin ledger

  • Many copies
  • Public writes
  • You verify yourself
This comparison shows up again with Postgres vs Ethereum. Plant the seed. Ask the room: "If everyone can see and copy the ledger, how do you stop someone from rewriting history?" That question opens PoW.

Part 02 · Security without a boss

How do strangers agree
on the next page?

Don't say Proof of Work yet. Describe the problem first: thousands of computers, conflicting versions, who wins? Then introduce the race.

Diagram · Proof of Work

Miners race. Winner appends the block.

Waiting txs
→
Miner A
Miner B
Miner C
→
New block

Competition replaces authority. Hardest to fake = most work done.

NOW name it: Proof of Work (PoW). One sentence: miners burn electricity solving a puzzle; first correct answer gets to write the next page and earn a reward. The chain is secure because rewriting history means redoing all that work.

First touch · waiting room

Before a miner picks your tx…

it sits in a public waiting room.

We'll name this properly later. Just remember: nothing is private while it waits.

Don't say "mempool" yet if you can help it — or say it once softly. This is foreshadowing. Point at the diagram's "Waiting txs" box. Tell them we'll open a live website after Ethereum basics.

Part 03 · Ethereum arrives

Bitcoin = money ledger.
Ethereum = money + programs.

Bridge fast. Bitcoin proved the ledger. Ethereum asked: what if the ledger could also run code? That's the jump from "send coins" to "deploy apps."

PoW → PoS

Ethereum switched how it picks the next block.

PoW race with energy
PoS stake ETH, get chosen

Why? Mostly energy + throughput. One sentence, not a debate. Same public ledger idea.

Name Proof of Stake (PoS). Don't get dragged into "which is better." For this audience: validators lock ETH as collateral; if they cheat, they lose it. Security via skin in the game instead of electricity bills.

Paying for block space

Gas = your bid for computation

low fee → slow
mid fee → normal
high fee → first

Same auction logic as "who gets into the next block." We'll see this live on the mempool screen.

Name gas. Analogy: Uber surge pricing for CPU on a shared computer. Every opcode costs gas; you set a max you're willing to pay. Higher tip = miners/validators prefer you. This connects directly to sandwich attacks later.

Live · mempool.space

Every transaction you're about to see is a public message telling the whole world what someone is about to do.

Open the tab. Don't explain yet. Let them watch.

mempool.space ↗
THIS is the hook — but now they have vocabulary. Switch to the projector on mempool.space. Stay silent for 10–15 seconds. Then: "You now know what a block is. That waterfall is the waiting room. We'll come back and dissect it after Solidity."

Part 04 · Mental model

Ethereum is a shared spreadsheet
that can compute.

Thousands of independent nodes keep the same copy and re-run the same maths.

Steal the Week 4 vibe: shared state machine. Emphasise "compute" — not just balances. That's why apps live here.

Analogy

Postgres

  • One owner
  • Private writes
  • You trust the DBA

Ethereum

  • Many owners
  • Public writes
  • Everyone re-executes
CS students get this instantly. "INSERT is a transaction. SELECT is free-ish. Everyone sees your INSERT in the pending queue." Perfect bridge to EOAs next.

Accounts

You don't "log in."
You hold keys.

EOA account controlled by a private key
Wallet app that manages those keys (MetaMask)
Transaction a signed message: "do this, I authorize it"
Name EOA. Demo MetaMask for 30 seconds if set up — show address, no seed phrase on screen. Signed message analogy: like signing a cheque, but the cheque is broadcast to everyone.

Under the hood · EVM

The EVM is the shared CPU.

Solidity
→
Bytecode
→
Every node runs it
→
Same new state

No opcodes today. Mental model: deploy code once → the world re-executes it forever.

Name EVM. Pull from Week 4 lightly: compilation produces bytecode + ABI. ABI is the "menu" wallets use; bytecode is what nodes run. Keep conceptual — "public program with public memory" is the line they should leave with.

Part 05 · Smart contracts

A smart contract is a
public program with public memory.

Repeat that line twice. Language is secondary. State = memory everyone can read. Functions = the API. msg.sender = who signed the call.

Concepts before code

state variablespermanent storage on-chain
functionsways to read / change state
msg.senderthe address that signed this call
visibilitywho can call what (public / private…)
Tie visibility to Week 3 quickly if anyone from WEC is here — otherwise skip. Focus on msg.sender: it's how "identity" works without usernames.

Full example · Counter

contract Counter {
    uint256 public count;

    function inc() public {
        count += 1;
    }

    function incBy(uint256 n) public {
        count += n;
    }
}

Walk line by line. Each line maps to Part 04.

Line-by-line: contract = deployed program. count = public memory. inc = anyone can bump it. Ask: "Who paid gas? Whose msg.sender?" Optional: show Remix deploy on Sepolia if time.

Tiny transfer sketch

mapping(address => uint256) public balances;

function transfer(address to, uint256 amt) public {
    require(balances[msg.sender] >= amt);
    balances[msg.sender] -= amt;
    balances[to] += amt;
}

A token is mostly a mapping. "Send" = subtract + add. (ERC-20 is this idea, standardised.)

Week 3 gold: token = mapping. Don't teach full ERC-20. Just plant: DEXs swap these mappings. That's what sandwich attacks prey on.

Part 06 · The waiting room

Back to the live screen.

Name it: mempool

Memory pool — pending transactions, not yet in a block.

Return to mempool.space. Now explain. Point at pending txs, fees, confirmation. This is a crux section — slow down.

How it spreads

Gossip, not upload-to-server.

You
Node
Node
Node

Your wallet sends the signed tx to a few peers. They tell their peers. Seconds later, the world can see it.

One-liner on gossip protocol. Week 4 RPC point: your MetaMask talks to one node (Alchemy etc.); that node gossips. Anyone running a node — or using a public explorer — can watch pending txs.

Ordering

Fee decides who goes first.

0.5 gwei
2 gwei
40 gwei ★
1 gwei
25 gwei ★

Validators prefer higher tips. Searchers know this. That's the attack surface.

Connect gas auction → mempool ordering. Anyone can read pending swaps and insert their own txs around yours by paying more. Set up MEV.

The uncomfortable fact

If it's pending,
it's already public.

Balances, amounts, destinations, contract calls — readable before confirmation.

Let it land. This is why "transparent blockchain" is a feature for verification and a bug for privacy. Transition: people make money from reading this feed. That's MEV.

Part 07 · Extraction

MEV

Maximal Extractable Value —
profit from choosing what goes in a block and in what order.

One-line definition. Formerly "miner" extractable; same idea with validators/builders. Searchers scan mempool for profitable reordering.

Sandwich attack · the mechanic

Victim wants to swap. Searcher eats both sides.

1. Front-run
buy first → price up
2. Victim swap
worse price
3. Back-run
sell → pocket spread

Draw this on a whiteboard too. Arrows: searcher tx → victim tx → searcher tx in the same block.

Walk slowly. Victim submits large Uniswap buy. Searcher sees it in mempool, buys first (price rises), victim buys high, searcher sells into that. Victim's slippage is searcher's profit.

Interactive · sandwich timeline

Victim tx appears in mempool

Swap 10 ETH → TOKEN. Slippage 1%. Public. Searcher bots are watching.

Searcher front-runs

Higher gas. Buys TOKEN first. Pool price moves up before victim lands.

Victim executes

Same swap, worse rate. Still "succeeds" within slippage — silently taxed.

Searcher back-runs

Sells TOKEN into the victim's buy. Spread = MEV profit. Block sealed.

Click through live. Students love this. Then jump to the Foundry repo demo.

Part 08 · Bigger than DeFi

Any mempool observer can profile a wallet.

  • Balances over time
  • Counterparties
  • Timing patterns (salary? treasury?)
Example: journalists or competitors watching a DAO treasury wallet. Or employers correlating payday. Finance as a public group chat.

The metaphor

Public blockchains are a
group chat for money.

Verification needs transparency. Humans need privacy. That tension is the course.

This sets up the whole "Make Private Apps" theme. Don't sell a product — sell the problem.
